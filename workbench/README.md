# FriesGo 本地客户开发工作台 0.4

在本机管理客户、项目机会、双语开发信与跟进记录，打开浏览器即可使用，无需 ChatGPT 或 Apple 登录。服务只监听 `127.0.0.1`，数据保存在本机 SQLite。

## 启动

需要 Node.js 24 或以上及 npm。首次安装依赖需要联网；构建完成后，客户管理、历史查询和 Word 导出在本机执行。

```bash
cd workbench
npm ci
npm run check
npm run build
npm start
```

打开 **http://127.0.0.1:5173**。macOS 会自动打开浏览器，也可双击本目录的 `启动工作台.command`。其他系统可手动打开网址。

停止服务：`npm stop`，或在 macOS 双击 `停止工作台.command`。关闭浏览器不会停止服务。再次使用执行 `npm start`；电脑重启后也需要重新启动服务。重复启动不会创建第二个实例。

不自动打开浏览器：`npm start -- --no-open`。依赖变化时重新执行 `npm ci`；源码更新后执行 `npm stop`、`npm run build`、`npm start`。重建不会清除 `data/`。

## 已包含

- 客户查询、国家和阶段筛选、联系人登记、官网及已核实社媒入口。
- 项目与多个客户关联，区分建设阶段、采购状态、预计采购窗口及其依据。
- 双语开发信版本、中文对照、回复话术和可替换签名。
- 实际沟通时间线、到期任务及下一步安排。
- 全局与单家客户的操作历史，按时间、客户、类型、动作和关键词筛选，展开对照修改前后。
- 开发信复制时的草稿快照，以及登记实际联系时冻结的双语正文。复制、生成文件与发送分别记录。
- Excel（.xlsx）跟进表的工作表选择、列映射、逐家预览和确认迁入，保留来源并区分计划、实际发送和无日期回复摘要。
- Word（.docx）客户资料与双语稿的解析预览、人工核对与确认写入；普通正文可另存为客户内部参考备注。
- 兼容研究 JSON 导入、批次去重、完整 Word 导出及包含历史的 JSON 备份。

旧日志保留其原始信息；启用历史前没有保存的修改内容无法补回。普通保存与其历史记录在同一事务提交，重复保存、过期版本和失败写入不会生成成功修改记录。研究/Word导入保留人工负责人、跟进日期和停止联系状态；Excel默认也保留，只有明确勾选迁入安排后才按非空原表值更新。

## 数据与备份

本目录 `data/friesgo.sqlite` 是运营数据库；`data/service.json` 与 `data/service.log` 是本地启动状态和日志。它们全部被 Git 忽略。更新本地代码前，先停止服务并备份整个 `data/` 目录；也可在网页内下载 JSON 备份。

`local/dist/` 仅存构建产物。数据目录独立于构建目录；可通过环境变量 `FRIESGO_DATA_DIR` 指定另一绝对目录。填写后的记录、买方回复、签名及运营备份只在私有副本保存。

公开的 `app/seed.json` 是2026年10月24日整理的 **24家公司初始研究与草稿**，包括24组中外文开发信和13类回复话术，不包含真实联系日志、买方回复、签名或运行中的数据库。部分联系方式仍标记待复核；原计划日期不代表发送。该初始组合与仓库根目录的20家渠道候选池是独立资料，编号和角色不互相覆盖，也不表示24家均满足渠道准入条件。

FriesGo Global 的供应商定位及产品事实边界沿用仓库规则；公开研究不证明当前采购需求。未启用自动发信、自动项目监测、多人登录或手机局域网访问。

## 源码位置

`app/` 保存界面及业务逻辑；`local/` 保存 SQLite 适配、本机 HTTP 服务和构建/启动脚本。构建时把原业务层的 `cloudflare:workers` 存储接口映射到 `local/database.ts`；运行时不依赖 Cloudflare 或 Sites，不包含云端站点配置或认证凭据。

## Word 资料录入

在“资料录入”选择未加密的 `.docx` 文件（不超过8MB），解析后勾选客户、补充缺失字段，再点击“检查选中资料”和“确认写入这些资料”。解析本身不写入客户记录；原文件不上传到外部服务，也不进入 Git。

支持公司/国家/官网/邮箱等列的客户表格、带字段标签的段落、编号客户标题，以及本工作台和原24家双语信文档的客户与草稿结构。缺少国家时需手动补充，空值和待补充字段不会覆盖已有内容。多封草稿只预览当前识别到的一封并提示，其他版本应分别录入。

Word中的项目、联系人明细、签名、回复话术库、跟进状态和历史操作不自动恢复；需要的普通文字可选定已有客户后保存为内部备注（最多5500字）。不会自动认定为采购需求、客户回复或已发送。旧 `.doc` 请另存为 `.docx`，扫描图片暂不支持 OCR。

## Excel 客户跟进表录入

进入“资料录入 → 从 Excel 跟进表录入”，选择不超过8MB的 `.xlsx`。默认识别“客户总表”；也可选择其他工作表，调整表头行及列对应关系。单批最多100家，逐家核对、勾选后点击“检查 Excel 选中资料”，再确认写入。旧 `.xls` 需先在 Excel/WPS 中另存为 `.xlsx`。

- 以公司名称、国家及官网辅助匹配已有客户，原表数字ID仅保留作来源，不强行对应系统编号。缺少国家时需补充。
- 可迁入客户资料、具名联系人、原表实际发送日和客户回复摘要。计划发送/第4、10、20天跟进日期不代表实际执行；无日期回复作为内部参考备注，不补造发生日或认定为人工采购意向。历史发送不自动关联此次旧稿，避免把候选稿当作当时发送正文。
- 已有客户的阶段、负责人和下一步安排默认不变；需明确勾选“同时迁入当前阶段、负责人和下次安排”，预览对照后才按原表非空值更新。未知阶段只作参考，不自动升级。
- 双语稿需在每家客户下单独勾选迁入，作为候选版本保存。原表邮件若是无缓存公式，可从同表“模板”工作表按邮件版本整理旧稿，仅替换公司占位符；签名及其他占位符保留，文案和产品事实需复核。
- 不执行公式、宏或外部链接；仅读取保存值。公式缺少结果或报错时提示单元格位置并留空。日期支持 Excel 1900/1904日期系统。
- 原文件留在本机；来源文件名、工作表、行号和每次修改进入操作历史。导入在一个事务提交，失败整批回滚；相同批次、草稿和历史迁入记录去重。预览后若相关客户或安排已改变，需要重新检查。

Excel解析、Word解析与本地数据库均不需要 ChatGPT 登录；自动发送和联网核验不属于文件导入。
